# conveyor plan

Phase plan, retros and backlog. The approved plan of 2026-09-10 follows; retro outcomes are appended per phase.


## Context

A change leaves the laptop and travels PR → merge queue → main build → staging/prod. Today that
state lives in four browser tabs plus `kubectl`. conveyor is a Rust + Ratatui TUI that shows all
four stages side by side, one column each (your sketch), with status per row and actions on the
selected row. Built with `/tdd autonomous`, one repo (`piacsek/conveyor`, already created, public,
empty), Homebrew install via the existing `piacsek/homebrew-tap`. Process and tooling are lifted
from `~/projects/tmux-agents` (`AGENTS.md`, CI/CD, formula script, test harness).

Decisions taken (your answers, 2026-09-10):
- GitHub access: shell out to `gh` behind a `Github` trait; fake in tests; `gh` shim on PATH for e2e.
- Layout: four side-by-side columns, focused column highlighted; collapse to tabs under a min width.
- Phase 1 row actions: open in browser (`Enter`/`o`), details pane (`p`), copy URL (`y`). Write
  actions (approve/merge/rerun) go to the backlog.
- Phase 4 fetcher: `kubectl` only; others stay in the backlog (see "Deferred").
- Cadence: run every phase's TDD cycles autonomously; pause only for the end-of-phase retro, whose
  learnings land in `AGENTS.md` and re-plan the next phase.

## Verified facts driving the design (checked 2026-09-10)

**Toolchain**: rustc/cargo 1.98.1, `gh` 2.98.0 logged in as `piacsek` (keyring, ssh), `kubectl`
at `/usr/local/bin`, `tsh` via asdf. Crate latest: ratatui 0.30.2, toml 1.1.5, insta 1.48.0,
serde/serde_json 1. Rate limits: core 5000/h, graphql 5000 points/h, search 30/min.

**My PRs**: GraphQL `search(query:"is:pr is:open author:@me archived:false", type: ISSUE)` returns
per PR: `number title isDraft reviewDecision mergeStateStatus statusCheckRollup{state contexts{…}}
mergeQueueEntry{position state} updatedAt url headRefName repository{nameWithOwner} additions
deletions comments{totalCount} reviews reviewRequests`. Check contexts are a union of `CheckRun`
(`name status conclusion detailsUrl`) and `StatusContext` (`context state targetUrl`). Your four
open PRs are drafts with `mergeStateStatus: UNKNOWN` (GitHub computes it lazily);
treat UNKNOWN as "—", not as an error.

**Merge queue** (a large monorepo with a merge queue): `repository.mergeQueue{ url configuration{mergeMethod
maximumEntriesToBuild minimumEntriesToMerge mergingStrategy} entries(first:20){ nodes{ position
state enqueuedAt estimatedTimeToMerge solo jump headCommit{oid statusCheckRollup{state}}
pullRequest{number title author{login}} } } }`. Config today: SQUASH, build 5, merge 1, ALLGREEN.
Entry `state` ∈ AWAITING_CHECKS | LOCKED | MERGEABLE | QUEUED | UNMERGEABLE. Queue is empty at the
moment; merge-group workflow runs are visible with `gh run list --event merge_group` on branches
`gh-readonly-queue/main/pr-<N>-<base sha>` with `displayTitle` = workflow name (useless for the
row; use the PR from the queue entry, or parse `pr-<N>` from the branch for runs whose entry has
already left the queue). Rulesets endpoint returned nothing for the probed repo (classic protection), so the GraphQL
queue object is the only source.

**Main builds**: `CI/CD` (`.github/workflows/cicd.yml`) runs on `push` to `main`, `merge_group`
and `pull_request`. Many other workflows also run on main (`Claude PR Assistant` on
`issue_comment`, `apps/* deploy`), so the "main build" workflow must be configured per repo;
default `CI/CD`. REST `repos/{r}/actions/workflows/cicd.yml/runs?branch=main&event=push&per_page=10`
gives `status conclusion head_sha display_title actor run_started_at updated_at html_url`.
Squash titles end in `(#4821)`, and `repos/{r}/commits/{sha}/pulls` maps sha → PR + author for the
rest. `history(first:10)` GraphQL with `associatedPullRequests` is the one-query alternative.

**Deployed**: Argo CD image-updater pins a 40-hex sha per env in
`<gitops repo>/<app>/{dev,staging,prod}/image-updater.yaml` (`image.tag`), `newest-build`
strategy. kubectl contexts come from teleport, one per environment (staging current). `tsh status`
shows the session **expired**, so a fetcher failure is the normal case, not the exception: the
row shows the error and the app keeps running. GitHub Deployments API only records `staging`.
Repo env names: Production, staging, Preview, copilot. sha → PR via `commits/{sha}/pulls`;
"n behind main" via the main-builds list.

**Repo state**: `/Users/piacsek/projects/conveyor` has `.git` (remote `piacsek/conveyor`, zero
commits) and an empty stray dir `~/scratch.nvim` (nvim scratch plugin artifact) — delete it in
phase 0 before the first commit and add `~/` to `.gitignore` so it cannot come back.

**Homebrew**: tap `piacsek/homebrew-tap` (local clone `~/projects/homebrew-tap`), formula
generated by `scripts/homebrew-formula.sh <version>` from release `.sha256` files; the `tap` job
pushes with the `TAP_TOKEN` secret. That secret is per repo: you must run
`gh secret set TAP_TOKEN --repo piacsek/conveyor` with the same fine-grained PAT (contents:write on
homebrew-tap) before the first tag. Formula name `conveyor` (no homebrew-core collision matters:
install is tap-qualified `piacsek/tap/conveyor`), `depends_on "gh"`.

## Architecture (all phases)

```
Cargo.toml               name conveyor, edition 2024, rust-version 1.98, release profile lto/codegen-units=1/strip
src/main.rs              glue: cli::parse → config::load → spawn fetch threads → app::run with a crossterm+channel input iterator
src/lib.rs               pub mod cli, config, github, kube, model, app, ui, text, open, fetch
src/cli.rs               `conveyor` (TUI) | `config` | `--help/-h/help` | `--version/-V/version`; hand-rolled, no clap
src/config.rs            Config (serde+toml, deny_unknown_fields, every table optional), XDG path, CONVEYOR_CONFIG override, validate(), to_toml()
src/github.rs            trait Github { graphql(query, vars) -> io::Result<serde_json::Value>; rest(path) -> …; run(args) -> … }; CliGh (spawns `gh`, maps NotFound → "gh not found on PATH; install gh (brew install gh)", non-zero exit → stderr text)
src/kube.rs              trait Kube { image(context, namespace, deployment) -> io::Result<String> }; CliKubectl
src/model/prs.rs         PullRequest + parse(Value) -> Vec<PullRequest>; Check; ReviewState; MergeState
src/model/queue.rs       QueueEntry + parse
src/model/builds.rs      Build + parse (REST runs), pr_number_from_title
src/model/deployed.rs    Deployment { env, sha, pr: Option<PrRef>, behind: Option<usize> }
src/fetch.rs             Stage enum { Prs, Queue, Builds, Deployed }; fn fetch(stage, &Github, &Kube, &Config) -> Result<Rows, String>; refresh scheduler (per-stage interval)
src/app.rs               App { columns: [Column; 4], focus, mode: Normal|Filter|Help|Details, error }, Input { Key, Data(Stage, Result<Rows,String>), Tick }, Action { Continue, Quit, Open(url), Copy(text), Refresh(Stage) }, run()
src/ui.rs                draw(): columns or tabs by width; KEYS table drives help; footer shows mode/filter/error/last refresh age
src/text.rs              truncate() with ellipsis (port from tmux-agents)
src/open.rs              trait Opener { open(url); copy(text) }; system impl (`open`/`xdg-open`, `pbcopy`/`xclip`)
scripts/homebrew-formula.sh, scripts/gates.sh (fmt, clippy -D warnings, test, test --ignored; fails loudly, never piped through tail)
tests/support/mod.rs     Harness { terminal: TestBackend, app, gh: FakeGithub, kube: FakeKube, opener: FakeOpener }, key()/ctrl()/data()/tick(), screen(), cell(x,y), row builders
tests/fixtures/*.json    verbatim `gh` output captured from a public repo (prs, queue, runs, commit pulls); refreshed when GitHub changes shape
tests/{prs,queue,builds,deployed,layout,config,cli,snapshots,e2e}.rs
```

Design rules carried over from tmux-agents (they go into `AGENTS.md`):
- `run()` is generic over `Backend` and an `Iterator<Item = io::Result<Input>>`; tests script
  `Input::Key`/`Input::Data`; main merges crossterm events and an `mpsc` channel fed by one fetch
  thread per stage. Draw before the first read.
- Side effects (open, copy, gh, kubectl) live behind traits; `App` is pure state. A failed action
  sets `App::error`, drawn red in the footer, cleared on the next key; the app never exits on it.
- Per-column state: `Loading | Ready(rows, fetched_at) | Failed(msg, last_rows)`. A failed refresh
  keeps the old rows dimmed with the error in the column title, so an expired `tsh` or a rate limit
  never blanks a column.
- Row order stable across refreshes (merge by key: PR number / run id / env), selection follows the
  key. Colors from the ANSI palette only.
- Lenient parsing: unknown enum values → `Unknown`, unknown fields ignored; verbatim fixtures.
- `--help`/`--version` print before config is read. Config errors name the file and key; TUI runs
  on defaults with the error in the footer; `conveyor config` prints effective TOML and exits 1 on
  a broken file.
- Gates before every commit: `scripts/gates.sh` = `cargo fmt --check && cargo clippy --all-targets
  -- -D warnings && cargo test && cargo test -- --ignored`, then `cargo install --path . --root
  ~/.local --locked` so the binary you run is the committed code.

Config (introduced minimally in phase 2 when a repo is first needed; phase 4 adds `deploy`):

```toml
[prs]
query = "is:pr is:open author:@me archived:false"   # gh search syntax, gh-dash style
limit = 20
refresh_secs = 60

[ui]
min_column_width = 36      # below 4×this the columns collapse to tabs
details_percent = 40

[[repo]]
name = "<owner>/<repo>"
main_workflow = "CI/CD"     # file name or display name
builds = 10
refresh_secs = 30

[[repo.deploy]]             # phase 4
system = "api"
[[repo.deploy.env]]
name = "staging"
fetcher = "kubectl"
context = "<kube context>"
namespace = "api"
deployment = "api"
```

With no `[[repo]]`, the repo is derived from the cwd git remote (`gh repo view --json
nameWithOwner`), so `cd <repo> && conveyor` works with zero config.

## Phase 1 — My PRs column

Deliverable: `conveyor` shows one column of your open PRs, refreshed every 60 s, with open /
copy / details / filter / help. Other three columns render as `not configured` placeholders so
the layout is real from day one.

Outside-in order (`tests/prs.rs` drives `run()` with scripted inputs; one failing test each):

1. Empty data → column titled `My PRs (0)`, body `no open pull requests`; `q` quits.
2. Loading state before the first `Data` input → `fetching…` in the body; a `Data` input replaces it.
3. Two PRs → rows `#4821 ✓ webapp  Retry webhook…  2h`; first highlighted; `1-9` jump.
   Row = number · check glyph (✓ success, ✗ failure, ● pending, ○ none) · title (truncated) ·
   repo · review glyph (approved / changes requested / review required) · draft marker · age.
4. `j/k`, `Down/Up`, `g g`, `G` move and clamp (port from tmux-agents).
5. `Enter` and `o` → `FakeOpener` recorded `open(url)`; app stays open.
6. `y` → `copy(url)`; footer flashes `copied #4821`.
7. `p` toggles details pane: checks list (name + conclusion, failures first), reviews, merge
   state, branch, `+adds −dels`; hidden below `ui.min_column_width × 2`.
8. `/` filter on number/title/repo with `query  matches/total` footer, `no matches for /q` body.
9. `r` → `Action::Refresh(Prs)`; footer shows `refreshed 12s ago` from `fetched_at`.
10. `Data(Prs, Err("gh: HTTP 401…"))` → column title `My PRs ⚠`, old rows kept dim, message in
    footer; next successful `Data` clears it.
11. Stable order + selection by PR number across a `Data` that reorders/removes.
12. `?` help from a `KEYS` table (12-row terminal like tmux-agents); `insta` snapshots for list,
    filter, details, error, empty, and the tab-collapsed layout at 80 columns.
13. `model::prs::parse` on `tests/fixtures/prs.json` (verbatim capture from the GraphQL search
    above, four drafts): unknown `reviewDecision`/`state` → Unknown; missing rollup → no glyph.
14. `CliGh`: argv builder tests (`["api","graphql","-f","query=…","-F","first=20"]`), exit code
    and stderr mapping, `NotFound` → install hint. `tests/e2e.rs` (`#[ignore]`): real binary with
    a `gh` shell shim first on PATH that prints the fixture; assert the screen is drawn before any
    key (the blank-until-keypress lesson).
15. `main.rs` wiring: fetch thread per stage → `mpsc` → `Input::Data`; `event::poll(250ms)` →
    `Tick` only drives the age labels. Reinstall, run against real `gh`, compare with
    `gh search prs --author @me --state open`.

16. Screenshots, same dynamics as tmux-agents: `scripts/screenshots.sh` renders `docs/*.png`
    from fixtures only (a `gh` shim on PATH, tempdir `HOME`, never the real account) through
    freeze → SVG → headless Chrome, README embeds them, and the documentation rule in
    `AGENTS.md` requires a re-render after any visible layout change.

Phase 1 exit: retro (see checkpoints), `AGENTS.md` updated, v0.1.0 tagged, plan phase 2.

## Phase 4 — Deployed column (kubectl fetcher)

- `[[repo.deploy]]` config as sketched; one row per env: `prod  #4790 (bob) Spike: parallel…
  ↓3 · 6d`, where `↓3` = commits behind main computed from the phase 3 list (or `—` when the sha
  is older than the list). `kube.rs` runs `kubectl --context C -n NS get deploy D -o
  jsonpath={.spec.template.spec.containers[0].image}`; tag after the last `:` must be 40 hex,
  else row error `unexpected image tag`. kubectl/tsh errors (expired session, no context) show on
  the row and keep the last known sha dim; refresh every 120 s.
- sha → PR via `commits/{sha}/pulls` (cached per sha; it never changes).
- Details: image ref, context, namespace, deploy age (`.metadata.annotations` or
  `status.conditions[Progressing].lastUpdateTime`), PR title/author, link to the PR and the run.
- `Fetcher` is an enum with one variant (`kubectl`) behind a trait, so `argocd-git`
  (read `<gitops repo>/<app>/<env>/image-updater.yaml` through `gh api …/contents`, no cluster
  auth) and `github-deployments` slot in later without touching the column.

## Phase 5 — cards and build details (requested 2026-09-10)

1. Footer: the rolling belt goes; a static, quirky conveyor logo with the version sits at the
   bottom right, dim.
2. `b` opens the build behind the selected card in every column: the PR's first failing (else
   first) check run, the queue entry's merge-group run, the build's run, the main build that
   produced the deployed sha. `Enter`/`o` open the item itself (PR when known).
3. Build details fetch the run's jobs on `p` (`repos/{r}/actions/runs/{id}/jobs`), failures
   first with durations, loaded lazily through a `Request::Jobs` from the TUI to a fetch thread.
4. Multi-line cards instead of rows: three lines per item, no row numbers (the `1-9` keys go),
   the selected card marked with a colored bar and bold title instead of `> `; dim lines below.
5. `R` refreshes every column; one braille spinner at the start of the footer replaces the
   per-title ones.
6. Docs, snapshots, screenshots, v0.5.0.

### Phase 5 outcome (2026-09-10)

- Shipped on `phase-5-cards` (PR #7), plan versioned as `plans/phase-5-cards.md`: the static
  `ui::logo()` with the crate version replaces the rolling belt; `b` opens the build behind any
  card (`App::build_url` per stage) while `Enter` on a build now opens the PR it merged;
  `R` → `Action::RefreshAll` and one footer spinner driven by `App::any_refreshing()`;
  `model::jobs` + `fetch_jobs` with a dedicated jobs thread and `Request::Jobs`; three-line
  cards with a cyan bar.
- Mid-phase the user asked for **more lines, not fewer**: "I wanna see what matters at a glance
  and rarely have to hit `p` or worse: go to the browser." So cards grew a third line carrying
  the unhappy checks, the failed job and its step, or the deployed sha, and failing main builds
  now fetch their jobs eagerly (`EAGER_JOBS = 5`) instead of only when selected.
- Two refactors the user asked for in the same pass: `ui.rs` (830 lines) split into
  `src/ui/{mod,style,card,columns,rows,details,footer,help}.rs`, and everything that talks to an
  external service grouped under `src/sources/` (`github.rs`, `kube.rs`, `fetch.rs`,
  `queries/`). `open.rs` stayed out: it is the OS seam, not a service.
- `Action::OpenBuild` was dropped from the plan: it would have carried a `run()` arm identical
  to `Action::Open`. `Action::LoadJobs` was dropped too: `run()` asks `App::jobs_needed()` after
  every input, which also covers the re-request after a refresh drops an unsettled run's cache.
- Deferred: job details for the queue's merge-group run and for a PR's check runs (only main
  builds fetch jobs); a per-column selection bar colour for the unfocused columns.

## Phase 7 — keys and the deployed lookup (requested 2026-09-10)

- v0.6.1: the sha → pull request lookup froze a miss for the life of the process, so a Deployed
  row read in the seconds after a rollout showed `no pull request found for this commit` until
  a restart. `fetch::Pulls` now retries a miss on a 120 s window, falls back to the `(#N)`
  squash suffix, verifies the pull request actually contains the commit, and never treats a
  `gh` error as an answer. Two sub-agent review passes drove the design; the second confirmed
  each finding of the first was fixed and killed by a mutation of its test.
- v0.7.0: `q` is the only quit key. `Esc` leaves zoom and otherwise does nothing, so an
  accidental press no longer ends the session. `z` still toggles zoom both ways.
- New working agreement, from the user: marking a PR ready for review means a sub agent reviews
  the branch diff first, and its findings are addressed before `gh pr ready`. Written into
  AGENTS.md.

## Risks

- `gh` output shape is stable but `mergeStateStatus: UNKNOWN` and lazily computed rollups mean
  rows can look "pending" for a few seconds after a push; show UNKNOWN as `—`.
- GraphQL search costs points per PR page; at 60 s refresh with 20 PRs it is far under 5000/h,
  but four stages × short intervals could add up: intervals are config and the footer shows the
  last refresh age so throttling is visible.
- Merge queue is empty today; phase 2 needs a live capture for the non-empty fixture. Fallback:
  hand-write from the GraphQL schema and mark it synthetic in `AGENTS.md`.
- Teleport sessions expire daily; phase 4 must never block the UI on `kubectl` (background
  thread + timeout via `kubectl --request-timeout=10s`).
- Edition 2024 + clippy `-D warnings` on toolchain bumps; CI pin matches local 1.98.1.
- `TAP_TOKEN` is a manual step; until it is set the `tap` job fails and the formula must be pushed
  by hand with `scripts/homebrew-formula.sh`.
